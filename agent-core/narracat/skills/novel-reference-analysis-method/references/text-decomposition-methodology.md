# 文本拆解方法论

> 本文件归 `novel-reference-analysis-method` 独有，由 `/narracat:reference` 命令按需 Read 加载。

---

## 一、为什么需要"文本拆解"

成品小说是高度耦合的语言产物。直接读"觉得不错"不会得到可注入下游 prompt 的材料——观感会变成"风格好"这类无可操作的赞美。

文本拆解的目的：把成品文本切回"作者做了什么决策"——句式、视角、信息节奏、对话呈现方式、修辞密度、标点偏好等——让分析产出可被 prompt 引用、可被审修对照、可被新作模仿。

## 二、拆解的三层粒度

| 层级 | 单元 | 关注点 |
|---|---|---|
| **段落级** | 一个 100-300 字的自然段 | 句式节奏、修辞密度、信息密度、视角切换 |
| **场景级** | 一个 300-1500 字的连续场景 | 场景开合、信息释放节奏、人物声音、情绪曲线 |
| **章节级** | 一整章 | 开篇钩子、转折设计、章末手法、价值转换、悬念布置 |

每次分析必须**显式选定一个粒度**，不要混合（如不要在段落级里讨论章节结构）。

## 三、五步拆解流程

### 步骤 1：选定维度与粒度

确定本轮分析关注哪个维度（premise / world / characters / structure / style 之一）以及哪个粒度（段落 / 场景 / 章节）。维度 × 粒度的组合决定后续提取方式。

### 步骤 2：分维度阅读

每次阅读只关注一个维度。理由：一次性混合分析会让产出滑向赏析腔（"整体很好"），而非可操作的手法清单。

阅读时做的事：

- 标注关键片段位置（行号或段落起止字符）
- 用一句话描述"作者在这里做了什么"（不评价好坏）

### 步骤 3：手法识别（提取"做什么/如何做"）

把标注转译成"决策语言"。例子：

| 原文观感 | 转译后的手法识别 |
|---|---|
| "对话写得活" | 角色甲句尾用"罢"，乙不用；甲句子平均 9 字，乙平均 21 字 |
| "环境描写不啰嗦" | 环境信息每段最多 2 句；剩余空间留给人物动作或对话 |
| "节奏快" | 章节平均 1800 字含 3 个场景切换；每场景结束有可识别的"结算句" |

**核心原则：转译的输出必须可被另一个写手照做。** 如果一条手法识别其他人看了不知道怎么执行，回到步骤 2 重新提取。

### 步骤 4：去标识化

转译后的手法识别中**不应出现参考作品的专名/角色名/具体桥段细节**。只保留可迁移的手法骨架。

不合格示例：

> 主角林霜寒在第三章用"霜冷三尺"的剑招打败了对手

合格示例：

> 主角学会的标志性技法在引入后两章内必有一次实战使用，构成"展示-验证"闭环

### 步骤 5：场景化标注

每个被提取的手法都要回答"什么情境下用"。三项必填：

- **适用场景**：什么情境下应参考此手法
- **借鉴点**：具体的手法决策（与原文同质的可迁移操作）
- **不应照搬**：原文中不能迁移的部分（专名、桥段、关系原型等）

## 四、常见陷阱与对策

| 陷阱 | 表征 | 对策 |
|---|---|---|
| **赏析腔** | "这段体现了作者深厚的功力" | 改为"做什么"句式：「这段把环境信息压缩到 1 句、给人物动作 6 句」 |
| **整体评价** | "节奏很好" | 量化或具体化：「平均 1.7 个场景/章；每场景 250-600 字」 |
| **专名残留** | 摘要含"林霜寒说" | 去标识化：「主角说」或「核心角色甲说」 |
| **粒度混合** | 在段落分析里讨论"章末钩子" | 分两轮：先段落级再章节级 |
| **借鉴=照搬** | 摘要里写"也写一个霜冷三尺" | 提炼到机制：「标志性技法在引入后两章内实战使用」 |

## 五、多文件融合策略

当 `bible/references/` 下有多个参考作品时：

1. **逐文件分析**：每个文件独立走完五步流程，产出单文件的手法清单
2. **横向对照**：列出 N 个文件在同一维度（如 style.句式节奏）的差异与共性
3. **提炼共性**：如果 N≥2 个文件在同一手法上一致，纳入"高置信度借鉴"
4. **单文件特色**：仅 1 个文件出现的手法标注"低置信度，谨慎借鉴"
5. **避免主导**：单个文件的强烈个人风格（如某作者的标志性长句）不应直接成为项目通用规则

## 六、与下游消费的契约

本方法论的产出有两类消费方：

- **写作消费**：「注入摘要 + 借鉴点」进入后续命令与写作上下文，作为创作约束
- **扫描消费**：「不应继承」清单作为抗抄袭代码扫描的项目特化黑名单源数据

因此每个手法清单必须**同时**满足这两类消费的需求——只写"做什么"不写"不能做什么"会让审修端拿不到反向约束。
