# novel-reference-analysis-method

> 本 Skill 仅供 `/narracat:reference` 命令显式调用。不被任何 Agent 注入，不被 setup/world/plan/write/review/rewrite 自动匹配。
>
> 本 Skill 只定义"如何分析"（方法论 + 维度框架）。"分析结果写到哪里、按什么文件结构组织"由 `commands/reference.md` 约定。

## 用途

为参考作品分析提供方法论与维度框架：从用户放在 `bible/references/` 下的参考作品（`.md` / `.txt`）提炼可被后续 command 直接喂给 prompt 的高密度材料。

输出材料的特征：

- 偏向"可注入摘要 + 可借鉴片段 + 不应继承"三段结构
- 不是赏析报告，不写"这种写法体现了..."的赏析句式
- 不含参考作品的专名 / 角色名 / 具体桥段细节 / 标志金句原文（仅描述手法和机制；详见「分析原则」§2「去文本化」+ §6「拒绝原文复制」）

## 文本拆解方法论

详见 `${CLAUDE_PLUGIN_ROOT}/skills/novel-reference-analysis-method/references/text-decomposition-methodology.md`（按需 Read 加载）。

核心步骤：

1. **分维度阅读**：每次阅读聚焦一个维度（premise / world / characters / structure / style），避免一次性混合分析
2. **手法识别**：提炼"做什么 / 如何做"，而非"为什么好"
3. **去文本化**：摘要句中不出现专名 / 桥段细节 / 金句原文 / 具体意象（详见下文「分析原则」§2 三类抽象规则 + §6「拒绝原文复制」）
4. **场景化标注**：每个借鉴片段附「适用场景」「借鉴点」「不应照搬」
5. **跨文件融合**：多个参考作品时先逐文件分析，再提炼共性

## 五个分析维度

| 维度 | 分析要点 |
|---|---|
| **premise** | 题材承诺、核心冲突、读者期待、情绪曲线、类型钩子 |
| **world** | 设定密度、规则露出方式、场景质感、信息解释方式（直说 vs. 暗示） |
| **characters** | 角色类型、关系张力、语言指纹、动机结构、矛盾性 |
| **structure** | 章节开合手法、转折设计、悬念布置、信息释放节奏、爽点/痛点分布 |
| **style** | 叙事视角、句式节奏、描写密度、对话风格、修辞密度、标点偏好；**叙述者腔调子项**见下文 |

每个维度的产出形态遵循「注入摘要 / 应该影响的决策 / 可借鉴片段 / 不应继承 / 来源依据」五段结构——具体文件结构与目标路径由 `commands/reference.md` 定义。

### style 维度的「叙述者腔调」子项分析框架

每个参考作品在 style 维度下额外提炼 5 个「叙述者腔调」子项（与 `commands/reference.md` 步骤 4 的 `style.md` 模板 5 子项一一对应；具体目标文件结构以 `commands/reference.md` 为准）：

1. **风格描述**（200-400 字 paraphrase）
   - **分析方法**：通读参考作品若干叙述段落，提炼整体气质的「做什么 / 怎么做」（语气、节奏、距离感、情感色温、与读者关系等），用自己的话重写，不直接引用作品中的描写句。
   - **输出形态**：200-400 字连续散文段，全程 paraphrase，不出现专名、不出现 ≥10 字原文。

2. **专属词汇**（10-30 个 tag）
   - **分析方法**：从作品中识别出反复出现、构成该腔调辨识度的词汇 palette（动词类型、修饰语习惯、声音指示词、领域术语类型等），做**类型化抽象**而非照搬作品原词。
   - **输出形态**：10-30 个抽象 tag 列表，每个 tag 描述词汇类型（如「带肌肉感的短动词」「文白夹杂的虚词」），不写具体原词；如必须举例则需明确标注「示意，非作品原词」。

3. **概念体系**（5-15 条要点）
   - **分析方法**：分析该腔调如何 frame 世界——叙述者用什么样的概念群把人、事、物组织起来（如「修行 = 江湖 = 武林」的概念合一、「江湖 / 庙堂 / 山野」的三元拆分、「人情 / 规矩 / 体面」的伦理坐标等），重在结构和坐标系，不在具体设定。
   - **输出形态**：5-15 条要点列表，每条描述一个概念群或一组对应关系，不写参考作品的具体专名。

4. **标志金句机制**（3-5 条机制描述，不是金句库）
   - **分析方法**：识别参考作品中能体现该叙述者腔调辨识度的若干「标志性句子」，但**不收录金句本体**——而是抽象出可复用的**机制描述**：句长区间 + 嵌入位置（独立段 / 段末点睛 / 借人物口）+ 语用功能（点题 / 转折 / 评议 / 反讽）+ 限定条件（仅在哪类场景下出现 / 多久出现一次 / 与什么前置情绪搭配）。
   - **输出形态**：3-5 条机制描述。**严禁列出原句**，即使是「最有名的那句」也必须 paraphrase 为机制（例：「嵌入式 8-15 字短句 + 借次要人物口说出 + 用于场景结尾点睛 + 必带一处辩证转折」）。

5. **不应继承反模式**（enumerate 清单，作为抗抄袭代码扫描的源数据）
   - **分析方法**：参考作品的具体专名 / 桥段类型 / 原文 ≥10 字片段 / 关系原型——只要复用就会引发抄袭风险的内容，必须尽量完整 enumerate；漏列由下游代码扫描兜底，但 produce 阶段力求穷尽。
   - **输出形态**：4 类清单——`专名`（人名 / 地名 / 物品名 / 门派 / 招式名等具体专有名词）、`桥段`（标志性桥段类型描述，不是细节复述）、`原文 ≥10 字`（具体禁止片段 enumerate，作为后续抗抄袭代码扫描的源数据）、`关系原型`（如「主角 + 师门 + 师姐」的具体三元组）。

> **设计约束**：上述 5 子项的输出全程遵循下文「分析原则」§2「去文本化」+ §6「拒绝原文复制」。「标志金句机制」子项是去文本化压力最大的位置，分析时**抗拒「为了精准而摘抄原句」的诱惑**——精准描述机制即可，不需要也不应当出现金句原文。

## 片段约束

- 每个维度最多 3-5 个可借鉴片段
- 单个片段建议 80-250 中文字，不超过 500 中文字
- 每个片段必须附「适用场景」「借鉴点」「不应照搬」三项
- 摘要句以"做什么"或"如何做"开头，避免赏析腔

## 分析原则

1. **多源融合**：参考作品有多个时，逐文件分析后提炼共性，避免单一作品风格主导
2. **去文本化**：摘要和借鉴点中不得出现：
   - **专名抽象为类型**：参考作品的具体角色名 / 地名 / 物品名 / 门派 / 招式名一律抽象为类型（如"侠客主角 + 隐世师门"，不写"陈平安 + 山下学派"）
   - **金句抽象为机制**：标志性句子一律抽象为机制（句长 + 嵌入位置 + 语用 + 限定，如"嵌入式 8-15 字 + 借人物口 + 可被辩证"），**不写原句**
   - **意象抽象为范畴**：桥段细节和具体描写一律抽象为类型与范畴（如"师徒山下学派 + 主角剑修觉醒"，不写具体场景；如"水墨远景 + 留白意象"，不写具体描写句）
3. **场景化标注**：每个片段必须能回答"什么情境下用这个手法"
4. **拒绝赏析腔**：摘要句以"做什么"或"如何做"开头，避免"这种写法体现了..."的赏析句式
5. **不应继承显式化**：「不应继承」是审修端的项目特化黑名单，必须列出具体可识别的禁用内容（如"主角名 + 配角名组合"、"师徒关系起手"、"某类设定术语"）
6. **拒绝原文复制**：分析时产出文件不应出现 ≥10 字连续参考作品原文片段。即使是"金句"也必须 paraphrase 为机制描述。原因：`style.md` 等 guidance 文件会长期注入后续命令与写作上下文，原文残留会触发抄袭风险。「不应继承.原文 ≥10 字」清单中列出的具体禁止片段属于黑名单源数据，**不属于本条所禁的「原文残留」**——它们是为下游代码扫描提供的合法 enumerate。

## 与其他 Skill 的关系

- **novel-style-reference**：内置的真人写作范例库（写作上下文与深审用），项目无关
- **novel-reference-analysis-method（本 Skill）**：项目特化的参考作品分析方法论，由 `/narracat:reference` 调用，分析后产物即"退场"，不再被任何下游 command 注入

后续 command 只读 `bible/reference-guidance/*.md` 文件，**不重新执行参考作品分析**。
